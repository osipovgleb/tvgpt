# Дайджесты: локальная проверка реализации

18 октября 2026. Ветка `codex/news-digests`, основная реализация `c1b4bbf`; самостоятельный Android-клиент, без выполнения пользовательских новостных заданий desktop-чатом.

## Выполнено локально

- Полная host suite `bash scripts/test.sh`: проходит, включая новые протоколы генерации, подбор/дедупликацию новостей, DST, статусы обложек и завершение/передачу фонового задания.
- Репозиторий, конфигурация и миграция вызывают настоящие SQL запросы через Python sqlite3 в отдельных host tests. Android API adapter заменён только в test scope; это проверяет SQL и политику, не Android lifecycle.
- SQLite-регрессии: сохранность legacy данных при v2→v3; operation ID/revision; замена обложки без создания/вытеснения выпуска; возобновление сохранённого выпуска; 101 расписание из разрешённых 400; защита используемых файлов и отказ при переполнении кеша; квоты; tombstone/logout.
- ARM32 APK, основной instrumentation APK и отдельный self-targeted SQLite/cover APK собираются. Подпись — существующим локальным development key; установки нет.
- Форматирование и архитектурная проверка проходят. AI Slop: 0 ошибок, 9 предупреждений о канонических URL подписки. Произвольный endpoint для удаления предупреждений не вводится.

## Независимый review

Одна независимая проверка выявила семь важных дефектов. Для них выполнен один цикл исправлений и повторная suite:

1. Cover-only запросы меняют изображение в исходном выпуске; репозиторий запрещает публиковать их как новые выпуски.
2. Возобновление читает сохранённые материалы; ключ генерации основан на нормализованном URL, а не изменчивом model story_key. Неопределённая отправка остаётся unconfirmed.
3. Eviction защищает ссылки сохранённых выпусков и активные pins; новая обложка отклоняется при нехватке места вместо удаления архивной. Один ограниченный временный файл до 16 MiB возможен сверх лимита готового кеша 200 MiB.
4. Планировщик читает все допустимые 400 расписаний, не только первые 100.
5. Явный запрос новой иллюстрации возвращает failed/unconfirmed при соответствующем исходе; прежняя фотография остаётся. Обычный дайджест с фотографиями может быть ready без imagegen.
6. Завершение JobService и новые запросы используют handoff; устаревший system pending snapshot не оставляет новую работу без запуска.
7. Метаданные конкретной статьи не следуют её site-wide RSS: картинка берётся у нужной публикации. RSS autodiscovery используется только при чтении источника.

## Первичная установка и границы проверки

По явной команде пользователя «установи» 18 октября ревизия b61c9d9 установлена на TCL через install --no-incremental -r. UID 10161 сохранился; аккаунт в UI показывает «Подключён», AssistantService и TvAccessibility реально привязаны, оба системных assistant-поля сохранены. Раздел «Дайджесты» открыт и наблюдён на снимке экрана. Не подтверждены доступность image_generation на аккаунте, фактическая картинка через подписку, интернет/RSS на самом TV, D-pad и читаемость, автозапуск DreamService вместо Google/TCL, standby/resume, взаимодействие с голосом и фактическая нагрузка ARM32. Сборка и host SQLite не заменяют этих наблюдений.

Imagegen не является условием работы дайджестов: приложение сначала публикует новости и фотографии сайтов; генерация работает дополнительно и не требует desktop runtime. Платный API автоматически не используется.

## Исправление выпуска «Спорт БО» — 18 октября

Первая установленная версия ошибочно превращала HTML раздела в одну новость. Её URL указывал на раздел, фотография статьи не извлекалась. Это не был подтверждённый рабочий новостной screensaver.

Исправление: раздел раскрывается в отдельные публикации, у «Спорт БО» выбираются активная тематическая вкладка и её статьи, без соседних видов спорта и recommended sidebar. Открывается каждая публикация; читаются articleBody или встроенный preloadnews, дата и фото. Поле pic имеет приоритет над иконками соцсетей в body. Источник фотографий — сама публикация. Фото не берутся из случайной другой новости или общей RSS. Синтетические тесты воспроизводят раздел, вложенные блоки, чужую вкладку, дату MSK, отложенное изображение и social-icon trap.

Приложение на TCL самостоятельно получило 18 кандидатов и выпустило 9 новостей. Вторая проверка на устройстве подтвердила фото у всех 9 материалов текущего выпуска: 1200×800 и 750×500, ненулевые локальные файлы и успешный BitmapFactory bounds decode. Сохранённые предыдущие выпуски остаются в архиве; галерея и слайд-шоу выбирают последний выпуск каждой подборки. Проверка полного архива возвращала 19 материалов, из них первые 9 — текущий выпуск; это не 19 новых новостей.

Подборка «Волейбол», источник https://sport.business-gazeta.ru/volleyball, расписание ежедневно 09:00 Europe/Moscow сохранены приложением через общие DigestCommands. Imagegen остался unconfirmed: получение сгенерированного изображения не подтверждено. Успешные фотографии сайта не зависят от этого исхода.

Фотографии и переходы наблюдались в настоящем DigestDreamService (mIsTest=false), а не только в DigestPreviewActivity. Системный UI TCL направляет стандартный выбор заставки в Google gallery; по поручению заменить заставку компонент выбран через разрешённое подключение, прежние значения сохранены в build/dream-settings-before.json. Ни Google Dream, ни TCL пакет не отключались. Приложение само secure settings не переписывает. Временные диагностические перезапуски из параллельного чата прерывали DreamService; это отличено от самостоятельного сбоя заставки.

Слайды переделаны: фото во весь экран, заголовок 28 sp до двух строк, подпись 16 sp до двух строк, источник и дата 11 sp. Огромный единый TextView удалён. Host suite, ARM32 APK и test APK собраны; quality: 0 ошибок, 7 существующих предупреждений о canonical URLs. Проверки живого голоса, длительного standby, выполнения завтрашнего расписания и длительного ARM32 memory soak этим не подменяются.

Автозапуск после бездействия подтверждён отдельным наблюдением: временный timeout 30000 ms, возврат на HOME, без service call/startDream в этом цикле, затем реальный DigestDreamService с mIsTest=false и изображением. После проверки возвращены исходные 600000 ms. Кнопка DPAD_CENTER завершила DreamService; это проверено свежим dumpsys dreams. Свидетельства: build/dream-automatic.txt, build/dream-automatic-photo.png.


## Отдельная модель и реальный imagegen

18 октября добавлен независимый сохранённый выбор «Настройки ассистента → Дайджесты → Модель дайджестов». Исходное значение копируется из обсуждения один раз, затем настройки независимы. Self-targeted Android preferences check сначала воспроизвёл перенос модели при миграции, затем подтвердил независимость, сохранение и безопасную обработку повреждённого значения. Тестовый пакет удалён. Строка также наблюдалась на TCL с выбранным gpt-6.1-sol.

Встроенный runtime-навык imagegen загружается агентом приложения; реальная подписочная генерация и показ картинки подтверждены. Подробные размеры, результат, протокол и исправление read timeout описаны в docs/imagegen-subscription-investigation.md. Desktop tool для создания иллюстрации не использовался. После проверки восстановлена привязка AssistantService/TvAccessibility, тестовый runner удалён.

Две дополнительные проверки с настоящим SQLite подтверждают: повторный сбор статьи без даты не продлевает первые 48 часов; четвёртый успешный выпуск удаляет самый старый из архива, а текущая галерея показывает только последний. Эти правила не менялись данным обновлением.
