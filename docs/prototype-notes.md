# TV GPT — исторические заметки прототипа

> Архив технических заметок до подготовки публичного репозитория. Текущие инструкции — в [README](../README.md) и [руководстве разработчика](installation-and-development.md). Упоминания локальных аудиофайлов и старых экранов ниже описывают прежние ревизии.

Android TV assistant prototype for a 32-bit TCL (Android 12). Runs directly on the TV: WebRTC microphone capture and live conversation through a ChatGPT/Codex account, and local TV controls. It is a custom Java protocol client, **not** a port of the official Codex CLI or TypeScript SDK.

## Build and test

Requires JDK17, Android build-tools35 (`aapt2`, `d8`, `zipalign`, `apksigner`) and Android35 `android.jar`. Current machine uses the existing toolchain at `/tmp/tvgpt-launcher/toolchain`; override `TVGPT_TOOLCHAIN` for another installation.

```sh
bash scripts/build.sh
bash scripts/test.sh
adb install --no-incremental -r build/tvgpt.apk
```

Dependencies are pinned in `dependencies.json`; build downloads and verifies them. The APK includes only ARMv7 native recognition/WebRTC libraries and the small Russian Vosk model. The local signing key stays under ignored `build/`; preserve it to install future updates without losing login.

## Use

Package: `local.tvgpt.assistant`, label: **TV GPT**. Include this package in VPN routing if needed. Open setup, grant microphone permission, sign in by device code with your own account, enable TV GPT in Accessibility, and select its assistant service. TV firmware may omit the selection UI; an already authorized ADB connection can configure it:

```sh
adb shell cmd role add-role-holder --user 0 android.app.role.ASSISTANT local.tvgpt.assistant 0
adb shell settings put secure voice_interaction_service local.tvgpt.assistant/.AssistantService
```

Accessibility must be enabled explicitly; preserve any other enabled services. The setup screen is available with:

```sh
adb shell am start -n local.tvgpt.assistant/.MainActivity --ez setup true
```

Setup includes a toggle for local wake listening, “Привет, телевизор”. The idle detector processes audio on-device; the live conversation sends audio to the cloud after invocation. Closing a conversation returns to wake listening if enabled. Switch wake listening off in setup to stop idle microphone capture. “Окей, Google” is not inherited from Google's proprietary recognizer.

Available tools: open installed applications by label/package, change volume, read accessible screen text, navigate directions/home/back/select, click accessible labels. Remote direction/home/back/select commands use a device-local ADB connection to 127.0.0.1:5555 with a unique key generated by this app. Setup has a local-remote pairing button; accept the TV debugging prompt for that key. The developer machine is not needed afterward. Accessibility remains the first source for screen labels and named clicks. Screenshot and coordinate-tap tools are a fallback for supported apps. Some TV interfaces do not support touch injection.

## Verified and limitations

Native WebRTC was installed and checked on this TCL after preserving the existing signing key and app data. Real wake invocation, input transcripts, output audio, delegated tool calls and return to local wake listening were observed. Connected Live PSS changed from 319.7 MiB (app + its WebView renderer) to 212.4 MiB (native app); a short interval CPU sample changed from 34.5% to 31.7% of one core. Host protocol/lifecycle/persistence tests pass. These observations do not establish reboot or long-duration reliability. See [device results and measurement limits](native-device-results.md) and [native architecture](native-performance.md).
Google's `com.google.android.katniss` background interactor held a competing microphone capture even after changing default assistant, and restarted after force-stop. For this TV setup its RECORD_AUDIO app-op was blocked (package and UID), with original modes saved in `build/original-google-audio-appop.txt`. Reliability after reboot is not yet verified. The experimental subscription protocol can change. The live model alias follows Codex's current voice default; an exact numbered Live snapshot is not guaranteed. Recognition model requires significant RAM and warm-up time.

YouTube on this TV exposes the Cobalt virtual d-pad: nine deliberately empty 10×10 nodes rather than actual screen labels (confirmed independently by UIAutomator and matched to Cobalt source). ADB does not recover a missing semantic tree; it provides actual remote key injection. Visual navigation may still need an occasional screenshot. Screenshot tool output can be sent to the model only when requested by the agent.

Credentials use AndroidKeyStore AES-GCM private storage. No desktop credential copying or API key is required. Authentication availability still depends on account entitlement and server policy. No credentials are logged.

## Rollback

Open setup and disable wake listening. Restore your prior assistant in system settings, or restore the saved values in `build/original-tv-settings.json` on the development machine. Remove TV GPT from Accessibility, preserving other services. Revoke the TV GPT ADB key in developer options if desired; Android does not offer removal of one trusted host on every TV firmware (the general revoke option removes all trusted hosts). Removing the package deletes its local account, ADB private key and model files:

```sh
adb uninstall local.tvgpt.assistant
```

Restore Google microphone app-op modes from `build/original-google-audio-appop.txt` as part of rollback (this machine originally had UID `foreground`, package `allow`):

```sh
adb shell cmd appops set --uid com.google.android.katniss RECORD_AUDIO foreground
adb shell cmd appops set com.google.android.katniss RECORD_AUDIO allow
```

To return to this TCL's Google assistant (only if this was your previous configuration):

```sh
adb shell cmd role add-role-holder --user 0 android.app.role.ASSISTANT com.google.android.katniss 0
adb shell settings put secure voice_interaction_service com.google.android.katniss/.search.serviceapi.KatnissVoiceInteractionService
```

## Action budget

A delegated request can use up to40 tool rounds, followed by a tool-free model reply summarizing the completed stage and remaining work. The earlier prototype stopped after6 rounds (including screenshots/readbacks); this premature cutoff was removed. A request to continue gets a fresh stage budget within the same agent conversation. `navigate` accepts `count`1–20 to batch repeated remote presses without a model round for each key. Interrupted batches report how many presses completed and do not retry already completed presses through another route.

### Voice interface and working context

The TV assistant popup is a transparent window containing only an animated blue/white orb (87 dp view size, half the original). The launcher opens only the dark settings/onboarding interface with grouped rows and centered vector icons. Conversation is always a separate orb popup; there is no main-screen orb. Startup plays `voice-start.ogg`, extracted from the installed official ChatGPT application and confirmed by the user; this proprietary asset is documented in `app/assets/VOICE_SOUND_SOURCE.txt`. It is not licensed as part of any open-source dependency.

The assistant key toggles the system voice window; the local wake phrase opens it. Recognized goodbye utterances such as «Заверши голосовой чат», «На этом всё, спасибо» and «Ну всё, наверное, спасибо большое» close locally, without Agent HTTP. Explicit stable partial phrases use450ms debounce; lone «спасибо» waits for final recognition. Negations and an assistant quoting those words do not close the call. Other goodbye requests are delegated as the natural request «Завершить текущий голосовой разговор», without a technical marker or spoken farewell. Recognition itself still requires Live to deliver a transcript or delegation.

Each assistant invocation starts a fresh working conversation, with context retained throughout that call. Previous conversations remain in the local SQLite archive; old conversations and shared knowledge are read only on explicit user request. The active workspace is saved privately under `files/codex/tv-assistant/session.json`. Final turns are saved immediately. Once the orb has disappeared and native media has released, a separate worker prepares the automatic description (60s debounce), without blocking the next call. Screenshots are removed from saved tool outputs. Logging out clears the workspace and invalidates pending credential-refresh writes.

Welcome/settings includes **Заменить Google на TV GPT**. It uses the app's authorized local ADB connection to set and verify both `assistant` and `voice_interaction_service`, then disables and verifies the Google voice package `com.google.android.katniss`. The native HOTWORD_DISABLE action remains a fallback if the firmware rejects package disable. Pair the local remote first if prompted. This is a platform handover, not permission to run arbitrary model-provided shell commands.

On this TCL, denied Google microphone appops did not always stop its proprietary HOTWORD capture from invalidating our recorder. Firmware rejected disabling Google's individual voice service component; neither disable attempt changed it. Do not equate dispatching HOTWORD_DISABLE with proof of a microphone fix: inspect recording activity and repeat open/close tests. Package-level disabling did succeed. After disabling Google voice, three consecutive assistant-key close/reopen cycles passed. TCL sometimes emits a hide/show pair on one key; AssistantInvocation suppresses its duplicate show. The app cleans up failed captures instead of leaving an inert error window. Reboot persistence is still unverified.

Local development uses Git only; no GitHub repository or remote is required.


### Background sound

Settings includes a toggle for ducking other apps during a call. AudioDucking requests Android transient MAY_DUCK focus and abandons it on close/failure; it never changes a shared stream volume. On-device checks observed Spotify lose focus with LOSS_TRANSIENT_CAN_DUCK while TV GPT held assistant focus, and regain normal focus when the popup closed. Android chooses the duck amount, normally around20%; exact10% or a functional arbitrary-percent slider is not supported by this TV's current app/shell permissions. A read-only shell probe confirmed MODIFY_AUDIO_ROUTING denied and anonymized playback configs with no player proxy. The UI states this limitation. WebRTC echo cancellation/noise suppression are enabled; no extra neural filter runs on the TV.

To restore the Google voice package during rollback:

```sh
adb shell pm default-state --user 0 com.google.android.katniss
adb shell cmd appops set com.google.android.katniss RECORD_AUDIO_HOTWORD allow
```

### Settings and close checks

The orb overlay stays nonfocusable so the underlying app keeps remote-key input. The remote pairing row displays progress/results inline, rather than in an offscreen header. The back arrow exits settings and closes an active popup. **Проверить помощника** explicitly requests a short diagnostic audio answer; ordinary assistant invocation still uses only the startup cue, without a spoken greeting. Granting microphone permission resumes the pending check.

On-device `DeviceCheck` mode `close-ui` injects a final user transcript into a connected call (not an acoustic speech test), checks local panel release within2 seconds, tests the actual remote row's loopback ADB pairing, and clicks the back arrow. Latest run:11ms local panel release, remote pairing and back exit passed. Instrumentation requires rebinding the services after it starts and again after it finishes. On an idle assistant with voice activation enabled, the microphone is used locally for the wake phrase; closing Live does not disable that setting.

## Development checks

```sh
npm ci --ignore-scripts
npm run quality
npm run format:check
bash scripts/test.sh
bash scripts/build.sh
```

Node and AI Slop are development-only and are not packaged in the TV app. AI Slop 0.14.0 is pinned; telemetry is disabled in `.aislop/config.yml`. The quality command also enforces Java layer boundaries (the tool's custom import analyser does not support Java). `npm run format:java` uses a checksum-pinned google-java-format 1.22.0. Current AI Slop result: 98/100, no errors or complexity findings, two deliberate canonical subscription endpoint warnings. The endpoints are fixed to avoid sending account tokens to arbitrary configured servers.

## App sections

The native app sidebar has Conversations, Shared knowledge, Reminders, Assistant settings, and Settings. Assistant settings contains Appearance and Voice groups built with the original shared SettingsRows component. Technical setup, the app timezone and background ducking are in Settings. There is no Home page, repeated section heading or permanent footer help. Voice conversations remain a separate system assistant session.

Appearance offers twelve orb colours using one cached texture and cached colour filters. Six speech presets change instructions; Quiet also lowers only the remote WebRTC audio track to35%. Pace is an instruction, not a guaranteed numeric playback rate. Voice candidates are checked by an isolated playback-only subscription call. They are selected only after final output and received audio; cancellation or failure preserves the existing voice. Candidate availability and receive-only SDP still need integration checks against the TV/account before release.

Conversation finals, dates and shared notes are stored in the built-in SQLite database. Archive imports do not invent missing historical turn times. Summaries run separately after call close with at least a60-second delay; they cannot execute tools or modify the active Agent history. Pending descriptions show a topic excerpt. Deleting an archive record does not clear the current working context.

Knowledge notes can be edited locally or through explicit voice requests. Revision checks prevent stale writes; notes are bounded to100 records with titles up to120 and text up to4000 Unicode characters. Model context includes at most8000 characters of shared knowledge as user data.

Reminders support calendar dates, timers, daily repeats and weekly weekdays. They **do not wake the TV**: due work waits for the screen to be interactive, then is claimed once. Only explicitly requested app launches and volume actions can be scheduled; arbitrary shell commands are unavailable. Exact-alarm access is checked in Access settings, with an honest delayed-alarm fallback. Notifications and the TV's Russian text-to-speech provide an offline fallback; missing language data leaves the notification. Final standby delivery, voice commands, previews and UI navigation require the combined app's device integration checks.

Independent device SQLite checks can run without restarting the assistant:

```sh
bash scripts/build-data-tests.sh
adb install --no-incremental -r build/tvgpt-data-tests.apk
adb shell am instrument -w local.tvgpt.sectionschecks/local.tvgpt.assistant.DataCheck
adb shell am instrument -w -e mode write local.tvgpt.sectionschecks/local.tvgpt.assistant.DataCheck
adb shell am instrument -w -e mode verify local.tvgpt.sectionschecks/local.tvgpt.assistant.DataCheck
adb shell am instrument -w -e mode preferences local.tvgpt.sectionschecks/local.tvgpt.assistant.DataCheck
adb uninstall local.tvgpt.sectionschecks
```

For an isolated worktree, `TVGPT_KEYSTORE=/absolute/path/to/the/existing/debug.keystore` uses the installed app's signing key without copying it. Do not uninstall the assistant to resolve a signing mismatch.
### Common app search and quiet TV interaction

`search_app(name, query)` is the shared search operation: it tries the target application's standard Android search, then discovers semantic search controls/fields and enters the full query, without choosing letters with DPAD. UI discovery is bounded and target-scoped; password and unrelated fields are excluded. `type_text(text, submit)` uses Accessibility SET_TEXT or a temporary local InputMethodService for Unicode editor input, restores the previous IME and never places text in shell commands. TYPE_NULL editors are rejected because accepted commitText did not change the actual YouTube field on this TCL. A YouTube URI adapter is the final fallback behind generic discovery; a real TV screenshot verified the Russian query «космос» and results. This is a shared search strategy with capability-specific fallbacks, not a promise that every app exposes searchable UI.

The runtime policy is bundled in `app/assets/skills/app-search/SKILL.md` and included in the agent's instructions. Delegated tasks receive one short natural acknowledgement; technical details and repeated intermediate steps are not spoken unless requested. Generic voice failures use a short message; diagnostic detail stays in logs/settings. Live delegation acknowledgement is enabled.

The orb shows connecting and closing states. Explicit stable close phrases received in user transcript chunks close locally after450ms without waiting for a full cloud turn or agent request; ambiguous partial «спасибо»/«всё» still wait for a final turn. Duplicate delivery is filtered; continued speech cancels a pending close. Native capture is muted immediately and the closing orb remains until resource release, followed by a short fade. A device test injected a recognized partial close and observed popup disappearance in780ms (not microphone-to-recognition latency). A separate actual close released native media in117ms. Direct pause/play uses idempotent Android media keys and bypasses agent planning.

Settings **Фоновый голосовой вызов** states the microphone/indicator tradeoff. Disabling it leaves the remote assistant button working and releases idle microphone/model capture. Existing user preference is preserved. Privileged hotword capture and the ordinary app recorder have different indicator behavior; this app does not hide Android's privacy indicator.

UI and setup changes must follow the [interface contract](ui/interface-contract.md) and [development/installation runbook](installation-and-development.md). Build checks and device installation are separate steps; respect the latest user authorization and record the installed revision in the status document.

Remote date/time selection uses year/month arrow rows with a day calendar and separate hour/minute arrow rows. The app timezone is persisted once in Settings → General. Voice focus previews cache only explicitly requested synthetic output as bounded WAV files, keyed by Live model, and play locally after preparation. Root screens do not repeat sidebar titles or show permanent footer instructions.
