# Голосовой помощник для TCL Android TV

## Цель
Пользователь вызывает помощника кнопкой микрофона на пульте. Поверх текущего приложения появляется небольшое окно. Пользователь разговаривает с GPT-Live через свой аккаунт ChatGPT с доступом к Codex; помощник выполняет команды управления телевизором и сообщает результат. После завершения окно закрывается и микрофон освобождается.

## Условия
- Проверенное устройство: TCL Smart TV Pro, Android 12 / API 31, только armeabi-v7a и armeabi.
- Весь исполнитель и интерфейс работают на телевизоре; компьютер используется только для разработки и установки.
- Модель работает в облаке, нужен интернет.
- Ранее на этом ТВ вызов стороннего ассистента кнопкой пульта работал. Новый сервис ещё не установлен и не проверен.
- Первая версия вызывается кнопкой пульта. Сохранение «Окей, Google» не является условием первой версии: ранее при смене ассистента штатное пробуждение переставало работать.

## Подход
Предпочтителен собственный Android-клиент с тонкой платформенной частью на Java/Kotlin и Rust-компонентами для протокола и исполнения. Полное переписывание Buddy не требуется. Альтернатива — порт Mobile Codex, но его ARM64-зависимости увеличивают объём работ. Внешний компьютер как постоянный исполнитель исключён требованием пользователя.

Нельзя обещать готовую сборку Codex под ARM32: официального бинарного релиза для этой архитектуры нет. До основной разработки необходимо установить, собирается ли минимально необходимый runtime с голосовым App Server. Если нет, отдельно оценить реализацию нужной части клиента по существующему открытому коду. Последний вариант не является готовым официальным Rust SDK.

## Интерфейс
Android VoiceInteractionService и VoiceInteractionSession обеспечивают системный вызов и окно ассистента. Компактная панель в нижней части экрана показывает состояния подключения, прослушивания, ответа, выполнения команды и ошибки. Доступны отключение микрофона и завершение разговора. Кнопка «Назад» закрывает окно и голосовую сессию. Панель не должна забирать навигационный фокус у приложения во время выполнения команды.

## Голос и авторизация
Ориентир — экспериментальный App Server realtime v3 с WebRTC. В официальном исходном коде предусмотрен путь с текущей авторизацией ChatGPT. Прямой WebSocket голосовой сессии, ранее потребовавший API-ключ, не используется как доказательство ограничения WebRTC.

Вход выполняется самим пользователем штатным браузерным или device-code способом выбранного runtime. Секреты хранятся в приватном хранилище приложения и не попадают в логи. Уже установленный ChatGPT не рассматривается как источник токенов.

Точная версия Live выбирается среди доступных данному аккаунту; поддержка именно GPT-Live 1.1 ещё не установлена. Ошибка доступа показывается явно; отдельная платная API-авторизация автоматически не включается.

Микрофон и вывод звука подключаются через Android audio API либо совместимую ARM32 WebRTC-библиотеку. Нельзя считать наличие реализации на Rust доказательством совместимости всех её зависимостей с Android ARM32.

## Управление телевизором
Исполнитель предоставляет ограниченный набор инструментов: открыть приложение, прочитать доступное дерево интерфейса, выбрать элемент, прокрутить, вернуться назад, перейти домой, изменить громкость, управлять воспроизведением при наличии разрешённого платформой доступа.

Основной путь — Android Intents, AudioManager и отдельно включаемый пользователем AccessibilityService. Для навигации используются действия над доступными элементами интерфейса. Обычное приложение не получает право произвольно посылать системные DPAD-события: если такой ввод нужен, потребуется отдельный механизм с разрешением, например поддерживаемый ТВ remote-протокол. Его наличие и возможность локального подключения пока не проверены.

ADB с компьютера допустим для разработки и проверки, но не считается реализацией автономного управления. Недоступное действие возвращает явную ошибку. Результат команды подтверждается состоянием устройства, а не только текстом модели.

## Порядок реализации и критерии приёмки
1. Проверить сборку и запуск необходимого ARM32 runtime на ТВ. Подтвердить отдельным этапом возможность голосового подключения с пользовательским аккаунтом.
2. Собрать Android APK: вызов с пульта открывает окно поверх приложения; «Назад» закрывает его. Начальная установка не меняет роль ассистента без готовности к проверке.
3. Подключить живой разговор: речь доходит до модели, ответ слышен через ТВ, перебивание останавливает ответ, завершение освобождает микрофон.
4. Подключить инструменты управления. Проверить открытие YouTube, возврат домой, изменение громкости и взаимодействие с доступным элементом интерфейса.
5. Проверить отсутствие постоянной зависимости от компьютера: завершить соединение разработки и повторить вызов, разговор и управление.

Интерфейс без работающего голоса, успешное принятие RPC без установленного звонка или команды, выполняемые только с компьютера, не считаются завершённой задачей.

## Основные риски
Перенос Codex и WebRTC-зависимостей на ARM32; доступность экспериментального Live для аккаунта; ограничения микрофона пульта; недостаточная доступность интерфейса отдельных ТВ-приложений. Каждый риск проверяется отдельно до расширения функциональности.
