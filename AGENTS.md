# TV GPT project facts

- Standalone Android TV assistant on a TCL Android 12 / ARM32. Keep it a system `VoiceInteractionService`, not just an app launcher. No desktop runtime dependency.
- User wants a dark settings-only main app (no orb or voice conversation there). The separate assistant popup contains **only** an animated blue/white cloud orb (87 dp diameter; half the initial 174 dp), no panel/text/buttons.
- Personal builds use the exact original short ChatGPT cue, confirmed by the user, staged as `voice-start.ogg` from the external private-assets directory. Audio binaries must stay outside the source repository. No spoken greeting. Its source/proprietary status is recorded beside the asset.
- Assistant remote button toggles conversation. Wake phrase starts it. Final user goodbye phrases end it. Release microphone and native system session on close.
- Each assistant invocation starts a new workspace conversation/UUID with empty context. Context persists within that call. Saved conversations and shared knowledge are retrieved only on explicit user request, using bounded conversation_search/conversation_read and knowledge tools. Live reconnects do not mean replaying old conversations. This is a custom subscription protocol client, not a full Codex CLI port.
- Never replay archived JSON as fresh session.context.append input. Do not inject old initial_items automatically. No automatic assistant-check prompt or spoken greeting to mask startup failures.
- Save final turns locally as they arrive. After the orb detaches AND native media releases, refresh the archive and schedule its automatic tool-free summary on a separate worker (60s debounce). Never wait for that work before closing or starting another independent call.
- At the user’s request the WebView microphone path is replaced with native audio-only WebRTC (Java lifecycle / C++ engine). Do not restore WebView or the old PCM/Base64/WebAudio bridge.
- TCL Google Katniss can reopen HOTWORD capture despite another default assistant and denied RECORD_AUDIO. The native HOTWORD_DISABLE action and denied appops were insufficient. Package-level `pm disable-user --user 0 com.google.android.katniss` succeeded and stopped the competing Google voice runtime. Welcome settings must provide the replacement button, verify both Android assistant settings and verify that package is disabled. Google TV launcher is a separate package. Restore with `pm default-state --user 0 com.google.android.katniss`.
- Native Google component disabling is rejected by this firmware. Do not claim it succeeded.
- During conversations use AudioDucking (transient MAY_DUCK focus) and release on close/failure. Never lower the shared music stream to duck background: GPT shares it. Exact per-app10% is unsupported with current app/shell privileges; UI must state system-managed level instead of a fake percentage setting. WebRTC AEC/NS remain enabled; no heavy extra filter.
- TCL assist key can emit hide(active) then show(~150ms) for one press; AssistantInvocation suppresses that duplicate. Three consecutive close/reopen cycles passed after Google voice package disable.
- Public GitHub publication is authorized by the user on 18 October 2026. Keep proprietary audio outside the repository; local builds may stage it from TVGPT_PRIVATE_ASSETS.
- Never build/publish containers or deploy from this development machine; never bypass git hooks.

- Keep the orb accessibility overlay NOT_FOCUSABLE, including after injected remote actions; settings and the underlying TV app must retain remote input.
- Closing commands must bypass Agent HTTP: Live delegates the natural request «Завершить текущий голосовой разговор»; never expose the legacy control marker in model instructions or spoken output. Recognized goodbye phrases close locally. Do not ask the coding model to close a call. Local wake detection can keep MIC active after Live closes; it does not send audio to Live.
- Main settings: remote pairing status belongs inline in its row. The explicit assistant-check button requests a diagnostic spoken answer; ordinary invocation remains cue-only.

## Development quality

- AI Slop 0.14.0 is pinned as a development dependency. Run `npm ci --ignore-scripts`, then `npm run quality` after edits; `npm run quality:json` provides machine-readable findings. Codex uses these project instructions; no automatic PostToolUse hook is installed.
- `.aislop/config.yml` enables analysis and disables telemetry. Do not disable checks just to improve the score. Fix defects; explain deliberate canonical subscription URL warnings rather than adding an arbitrary server override that can leak tokens.
- Run `bash scripts/test.sh` and `bash scripts/build.sh` for native transport changes. These verify host behavior and ARM32 packaging, not TV microphone compatibility.
- VoicePanel presents UI; VoiceSession owns call lifecycle; LiveSignalling adapts subscription protocol; voice/ owns native audio and WebRTC resources. Dispose on the serialized native worker before restarting wake capture.
- On-device audio, repeated invocation, routing, echo cancellation and performance need actual TV verification. Do not call them verified merely because the APK builds.

- Native WebRTC requires ACCESS_NETWORK_STATE as well as INTERNET / RECORD_AUDIO / MODIFY_AUDIO_SETTINGS. Build checks enforce these; missing network-state permission caused a JNI abort on this TV.
- In connect-tv.py clear the old binding, open settings, then restore bindings while the app is foreground and verify actual bound processes; reuse a detector across repeated onReady callbacks. Native on-device resource results and limits are recorded in docs/native-device-results.md.

- Current TCL native capture uses MIC at16000Hz, with no forced phone MODE_IN_COMMUNICATION. This matches the working wake capture format. Keep original capture path native. Real speech reached input_transcript.added and user confirmed hearing at05:36 on Oct18. PCM peak/RMS diagnostics log aggregate values only; do not record/upload microphone audio for routine diagnostics. RTP counters alone are not proof of speech reception.
